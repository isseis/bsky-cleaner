## 1. 背景と目的

### 1.1 背景

[プロジェクト概要](../../overview.md) にある通り、本ツールの設定は TOML ファイルに一元化し、秘匿情報（Bluesky の app パスワード）のみ環境変数（Docker 配布時は `.env` 経由）から取得する方針である。本タスクは、他の全コンポーネント（AT Protocol クライアント、クリーンアップエンジン、Slack 通知等）が依存する設定読み込み・検証の基盤を先に整備する。

### 1.2 目的（ゴール）

- TOML 設定ファイルと環境変数から、実行に必要な設定値を型安全な構造体として読み込めるようにする
- 設定ミスや改ざん（例: `retention_days=0`）を早期に検知し、fail-closed で起動を失敗させる

## 2. スコープ

### In Scope

- **F-001**: TOML 設定ファイルのパースと構造体へのマッピング
- **F-002**: 秘匿情報（app パスワード）の環境変数からの取得
- **F-003**: 設定値のバリデーション（型・範囲・必須項目）

### Out of Scope

- Slack Webhook URL のホスト一致検証（[0006_slack_notification](../0006_slack_notification/01_requirements.md) で扱う。ホスト検証は Slack 通知固有のロジックのため）
- 実行スケジュール文字列を cron に橋渡しする `print-schedule` サブコマンド（[0007_docker_distribution](../0007_docker_distribution/01_requirements.md) で扱う。CLI サブコマンドの実装を伴うため）
- 設定ファイルのファイルシステム権限チェック・改ざん検知（overview.md の「未確定・今後検討する事項」に挙げられている通り、初期リリースでは対象外と判断）

## 3. 機能要件と受け入れ基準

### F-001: TOML 設定ファイルのパース

TOML 形式の設定ファイル（パスはコマンドライン引数等で指定）を読み込み、Go の構造体にマッピングする。少なくとも以下の項目を含む: `retention_days`（保持日数）、`schedule`（cron 相当のスケジュール文字列）、実行タイムアウト、Slack Webhook URL（正常系・異常系）。

**Acceptance Criteria**:
- **AC-01**: 妥当な TOML ファイルを指定した場合、各設定項目が対応するフィールドに正しくマッピングされる
- **AC-02**: TOML の構文が不正な場合、明確なエラーメッセージとともに読み込みが失敗する
- **AC-03**: 指定されたパスにファイルが存在しない場合、明確なエラーメッセージとともに読み込みが失敗する
- **AC-04**: 必須項目が欠落している場合、読み込みが失敗する（デフォルト値で黙って補完しない）
- **AC-12**: TOML 設定ファイルの仕様（項目名・型・必須/任意・デフォルト値・記述例）を記載した開発文書（`docs/design/config_file.md`）が存在し、実装のフィールド定義と一致している

### F-002: 秘匿情報の環境変数からの取得

app パスワードや Bluesky アカウント識別子（handle 等）など、TOML に書かれるべきでない秘匿情報を環境変数から取得する。

**Acceptance Criteria**:
- **AC-05**: 定義済みの環境変数（例: `BSKY_APP_PASSWORD`）が設定されている場合、その値が設定として読み込まれる
- **AC-06**: 必須の環境変数が未設定の場合、明確なエラーメッセージとともに起動が失敗する
- **AC-07**: 環境変数から読み込んだ秘匿情報が、エラーメッセージや文字列表現（`%v` や `String()` 等）にそのまま含まれない（後続タスクでのログ・Slack 通知経由の漏洩を防ぐための土台として、値をラップする専用の型を用いるなどして対策する）

### F-003: 設定値のバリデーション

設定改ざん・入力ミスによる意図しない大量削除等の事故を防ぐため、値の妥当性を検証する。

**Acceptance Criteria**:
- **AC-08**: `retention_days` が 0 以下、または未設定の場合、fail-closed で起動が失敗する（全投稿即削除を防ぐ）
- **AC-09**: `retention_days` が正の整数として妥当な場合のみ読み込みが成功する
- **AC-10**: 実行タイムアウトが未設定または不正な値（0 以下等）の場合、fail-closed で起動が失敗する
- **AC-11**: Slack Webhook URL が設定されている場合、URL として妥当な形式（スキームが `https` であること等）を検証する

## 4. 非機能要件

- **NF-001**: `make fmt`・`make test`・`make lint` が成功する。
- **NF-002**: 設定ファイルの読み込み・検証は、他コンポーネント（AT Protocol クライアント等）に依存せず単体でテスト可能であること。
- **NF-003**: 秘匿情報（app パスワード）をログ・エラーメッセージ・デバッグ出力に含めないこと。
- **NF-004**: Go 1.26.2 以上でビルドできること。

## 5. スコープ外の根拠

- Slack Webhook のホスト一致検証は、Slack 通知機能に固有のドメイン知識（正常系/異常系 2 つの URL の関係）を伴うため、Slack 通知タスク側でまとめて扱う方が凝集度が高い。
- `print-schedule` サブコマンドは CLI エントリポイントおよび Docker 配布の実装に強く依存するため、それらのタスクで扱う。
- ファイル権限・改ざん検知は、実装コストに対して初期リリースでの必要性が低いと判断し、overview.md の「未確定・今後検討する事項」の通り対象外とした。

## 6. 成功基準（要約）

- AC-01〜AC-12 が test/static で緑。
- TOML ファイルと環境変数から設定を読み込み、不正な設定（特に `retention_days=0` 等の危険な値）を fail-closed で検知できる状態。
